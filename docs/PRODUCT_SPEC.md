# Event Alpha Korea — 제품 명세 (PRODUCT_SPEC)

> 문서 버전 0.1 · 작성일 2026-07-31 · Phase 0 산출물

---

## 1. 한 문장 정의

국내 뉴스에서 **투자 관련 이벤트**를 자동 추출하고, 그 이벤트의 **경제적 전파 경로**를 따라
국내 상장사 전체에서 **근거가 있는 관련 종목**을 찾아 제시하는 리서치 지원 도구.

## 2. 이 제품이 아닌 것

| 아닌 것 | 이유 |
|---|---|
| 뉴스 요약 서비스 | 요약은 입력이지 산출물이 아니다. 산출물은 **종목 리스트 + 근거** |
| 종목 추천 서비스 | 매수/매도/목표주가/비중 일절 제공하지 않음 (§7) |
| 테마주 스크리너 | 테마는 별도 그룹으로 **강등 표기**. 직접 근거와 섞지 않음 |
| 실시간 시세 서비스 | 시세·차트·수익률 없음. MVP는 사건과 기업 관계만 다룸 |
| 자동매매 / 백테스트 | 범위 밖 |

## 3. 대상 사용자

- **1차**: 제작자 본인(리서치 자동화 도구). 사건 → 종목 후보를 5분 내 얻는 것이 목적
- **2차**: 이벤트 드리븐 아이디어를 직접 검증하려는 개인 투자자·리서치 실무자
- **관리자**: 제작자 1인. 모든 공개는 관리자 승인을 거친다

## 4. 핵심 제품 불변식 (Invariants)

이 10개는 코드 레벨에서 강제되어야 하며, 프롬프트 지시만으로 만족시키지 않는다.

| # | 불변식 | 강제 지점 |
|---|---|---|
| I1 | 모든 노출 종목은 `companies` 테이블에 실재해야 한다 | 영향분석 LLM 출력의 `company_id`를 **후보 집합 멤버십 검증**으로 필터 |
| I2 | `stock_code`가 없는 기업은 공개 결과에 포함하지 않는다 | DB CHECK + 조회 쿼리 필터 + 테스트 |
| I3 | LLM은 종목명을 **생성**할 수 없다 | 이벤트 구조화 프롬프트에 기업명 출력 필드 자체를 두지 않음 |
| I4 | 모든 종목 연결에는 `evidence_sources` 행이 연결되어야 한다 | `event_impacts` → `event_impact_evidence` 필수(단, `thematic` 제외) |
| I5 | 근거 없는 연결은 `thematic`으로 강등되고 점수가 39점으로 캡된다 | 점수 계산 순수 함수 내 하드 룰 |
| I6 | 매수·매도·목표주가·진입가는 어떤 필드에도 저장/표시되지 않는다 | 금지어 린트 + 프롬프트 + 리뷰 체크리스트 |
| I7 | 기사 전문을 저장하지 않는다 | `news_articles`에 body 컬럼 없음. 스키마 자체로 불가능하게 |
| I8 | 승인되지 않은 이벤트는 공개 경로에 나타나지 않는다 | RLS: anon은 `status='published'`만 SELECT |
| I9 | 동일 이벤트를 중복 분석하지 않는다 | `event_id` 기준 분석 잠금 + `llm_calls` 멱등 키 |
| I10 | 사실과 추론을 구분해 표시한다 | `factual_summary`(기사 근거) vs `transmission_steps`(AI 추론) 분리 저장·분리 렌더 |

## 5. MVP 이벤트 유형 (10종)

`event_type` enum:

| 값 | 한글 | 대표 트리거 |
|---|---|---|
| `policy_regulation` | 정책·규제 | 보조금, 인허가, 규제 강화/완화 |
| `tariff_trade` | 관세·수출입 규제 | 관세 부과, 수출 통제, 쿼터 |
| `commodity_price` | 원자재 가격 변화 | 구리·리튬·희토류·원유·LNG |
| `supply_disruption` | 공급망 중단 | 항만/물류 마비, 부품 부족 |
| `production_halt` | 공장 화재·생산 중단 | 화재, 폭발, 파업, 정기보수 |
| `major_order` | 대규모 수주 | 수주 공시, LOI, 낙찰 |
| `contract_change` | 계약 체결·해지 | 공급계약, 해지, 소송 |
| `ma_control` | M&A·경영권 변경 | 인수, 매각, 지분 변동 |
| `asset_sale` | 자산 매각 | 사업부·부동산 매각 |
| `geopolitics_logistics` | 지정학·운송 차질 | 분쟁, 해협 봉쇄, 제재 |

투자 관련성이 없거나 위 10종에 해당하지 않으면 `is_investment_relevant=false`로 조기 종료(비용 절감).

## 6. 화면 요구사항

### 6.1 이벤트 카드 (`/`, `/events`)

```
┌────────────────────────────────────────────────┐
│ 07-31 14:22  [관세·수출입]        [분석완료]   │
│ 미, 중국산 변압기 관세 인상 검토               │
│ 사실요약 2줄 …                                 │
│ 핵심변수 대미 변압기 수입가격 ▲                │
│ 영향기간 중기(3~12개월)   확신도 62            │
│ 긍정 7종목 · 부정 3종목        원문 ↗ (3개 매체)│
└────────────────────────────────────────────────┘
```

필수 필드: 발생시각 · 제목 · 사실요약 · 이벤트유형 · 핵심변수 · 영향방향 · 영향기간 ·
확신도 · 긍정 종목 수 · 부정 종목 수 · 분석상태 · 원문 링크.

### 6.2 이벤트 상세 (`/events/[id]`) — 9개 섹션

1. **사건 요약** — 3줄 이내, 사실만. 추정 문장은 별도 배지로 구분
2. **경제적 전파 경로** — `event_transmission_steps` 순서대로 단계 표시 (AI 추정 배지)
3. **긍정 영향 종목** — 표 (아래 컬럼)
4. **부정 영향 종목** — 동일 구조
5. **공급망·2차 관련 종목** — `relation_type in (supply_chain, competitor, substitute)`
6. **단순 테마 종목** — `relation_type='thematic'`, 접힌 상태 기본, 낮은 신뢰도 명시
7. **확인해야 할 숫자** — `event_requirements.requirement_type='evidence_to_check'`
8. **가설이 틀리는 조건** — `requirement_type='invalidation_condition'`
9. **후속 이벤트** — `requirement_type='follow_up_event'`

종목 표 컬럼: 종목명 · 종목코드 · 시장 · 관련도 점수 · 영향 강도 · 직접/간접 ·
영향 경로 · 기업 연결 근거 · 근거 출처(링크) · 근거 확인일 · 데이터 신뢰등급.

### 6.3 기업 상세 (`/companies/[stockCode]`)

기본정보 · 주요 제품 및 노출도(`company_exposures`) · 최근 연결 이벤트 ·
긍정 이벤트 / 부정 이벤트 · 근거 자료 목록 · 검수 상태.

## 7. 관련도 등급 표기

| 점수 | 라벨 | 색/강조 |
|---|---|---|
| 90–100 | 직접적인 실적 영향 근거가 강함 | 진한 강조 |
| 75–89 | 직접 사업 관련성이 확인됨 | 강조 |
| 60–74 | 공급망 또는 고객 관계가 확인됨 | 보통 |
| 40–59 | 간접 영향 또는 추가 확인 필요 | 흐림 |
| 20–39 | 단순 테마 가능성 | 접힘 그룹 |
| 0–19 | 기본 화면에서 제외 | 관리자 화면에서만 |

**점수만 표시하지 않는다.** 툴팁에 7개 세부 항목 점수(제품 25 / 매출근거 20 / 지역 15 /
공급망 15 / 공시근거 15 / 최근성 5 / 테마 5)를 breakdown으로 노출한다.

## 8. 근거 배지 체계

| 배지 | 조건 |
|---|---|
| `공시 확인` | `evidence_sources.source_type='dart'` AND `verified=true` |
| `기사 확인` | `source_type='news'` |
| `AI 추정` | LLM 생성 텍스트(전파 경로, rationale, 요약) |
| `근거 부족` | 연결된 evidence 없음 → 자동으로 `thematic` 강등 |

## 9. 표현 규칙 (규제 리스크)

**금지** — 코드에 금지어 상수 배열로 두고 LLM 출력·관리자 입력 모두 린트한다.

```
지금 매수 / 지금 매도 / 매수 추천 / 매도 추천 / 목표주가 / 적정주가 / 적정 매수가 /
진입가 / 손절가 / 수익 보장 / 급등 예상 / 급등주 / 반드시 상승 / 반드시 하락 /
포트폴리오 비중 / 비중 확대 추천 / 맞춤 추천 / 유망주 / 수혜주 확정
```

**사용** — 긍정 영향 가능성 · 부정 영향 가능성 · 관련 기업 · 경제적 전파 경로 ·
확인해야 할 변수 · 근거 수준 · 시장 반영 여부 · 가설 무효화 조건.

> 참고: `수혜주`라는 단어 자체는 관용적으로 쓰이나, 본 서비스는 UI에서 **"긍정 영향 가능성"**
> 으로 통일한다. DB enum은 `positive/negative/mixed/uncertain`만 사용.

## 10. 저작권·데이터 원칙

- 저장 항목: **제목 · 네이버가 제공한 description 발췌 · 원문 URL · 언론사 · 발행시각**
- 기사 본문 크롤링·저장·재노출 **하지 않는다**. 스키마에 body 컬럼을 두지 않아 구조적으로 차단
- 모든 이벤트 카드/상세에 원문 링크 제공. 다중 출처는 전부 나열
- 공시 인용은 **출처(보고서명) + 공시일 + 발췌문(2문장 이내)** 형태로만
- LLM 생성 텍스트는 전부 `AI 분석` 배지 + 하단 고지문

**고지문(모든 페이지 푸터 + `/about`)**

> 본 서비스는 공개된 뉴스와 전자공시 정보를 자동으로 분석해 제공하는 리서치 지원 도구입니다.
> 투자자문·투자권유가 아니며, 특정 종목의 매수·매도를 추천하지 않습니다.
> 자동 분석 결과에는 오류가 포함될 수 있으므로 반드시 원문과 공시를 직접 확인하십시오.
> 투자 판단과 그 결과에 대한 책임은 이용자 본인에게 있습니다.

## 11. UI 방향

- 밝은 배경, 정보 밀도 높은 금융 터미널 톤. 카드 중심
- 색은 **긍정/부정에만** 사용(green/red). 나머지는 무채색 + 회색 톤 배지
- 애니메이션은 로딩 스켈레톤 외 사용하지 않음
- 모바일: 종목 표는 카드 리스트로 전환 (가로 스크롤 금지)
- 폰트: 숫자는 tabular-nums 고정폭

## 12. MVP 완료 기준 (수용 시나리오)

로컬에서 아래 10단계가 끊김 없이 동작하면 **MVP 1차 완료**.

- [ ] 1. 관리자가 `/admin`에서 "뉴스 수집" 실행
- [ ] 2. 네이버 뉴스 검색 결과가 `news_articles`에 저장됨 (중복 재실행해도 증가 없음)
- [ ] 3. 유사 기사가 하나의 `event`(status=`candidate`)로 묶임
- [ ] 4. LLM이 이벤트를 구조화 (`events` + `event_transmission_steps` + `event_requirements`)
- [ ] 5. 기업 DB 검색으로 후보 ≤100개 생성 (LLM 미사용, 결정론적)
- [ ] 6. 긍정·부정·간접 종목이 **종목코드와 함께** 출력
- [ ] 7. 종목마다 rationale + evidence 링크 표시
- [ ] 8. 관리자가 수정 후 승인 (`admin_reviews`에 기록)
- [ ] 9. 승인된 이벤트만 `/events`에 노출 (미승인은 anon 쿼리로 조회 불가)
- [ ] 10. 상세 페이지에서 뉴스·전파경로·종목·근거·무효화조건 전부 확인 가능

## 13. MVP 제외 범위

실적 발표 자동 분석 · 목표주가 계산 · 포트폴리오 · 커뮤니티 · 알림(푸시/메일) ·
자동매매 · 시세 연동 · 백테스트 · 다국어 · 결제.

## 14. Phase 0 가정 사항

승인 없이 진행한 합리적 가정. 다르면 Phase 1 착수 전에 정정 필요.

| # | 가정 |
|---|---|
| A1 | 프로젝트 루트는 `바이브코딩/event-alpha-korea`, Next.js가 루트에 위치 |
| A2 | 실시간 파이프라인은 TypeScript(Next.js Route Handler), 대량 배치는 Python (근거는 ARCHITECTURE §3) |
| A3 | 관리자는 1인. 별도 role 테이블 없이 `ADMIN_EMAIL` 화이트리스트 + `profiles.role` |
| A4 | 임베딩 차원 1536 (`text-embedding-3-small` 기준), provider 교체 가능하도록 추상화 |
| A5 | 초기 기업 커버리지는 KOSPI+KOSDAQ 전 종목 기본정보, 프로필 상세는 **시총 상위 500사 우선** 단계 구축 |
| A6 | 배포 전 MVP는 로컬 + Supabase 무료 티어에서 검증 |
